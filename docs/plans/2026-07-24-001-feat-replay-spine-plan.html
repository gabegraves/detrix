Goal Capsule

Objective. Make every admission verdict in this repository independently re-derivable from the local store, and make every claim the tool prints match the evidence it actually holds. Five units: append-only evidence snapshots (U1), digest-verified evidence pointers (U2), a detrix replay command (U3), a shadow-mode wording ceiling (U4), and coverage-boundary visibility (U5).

Authority. This plan governs scope and sequencing. Repo conventions in README.md and existing code style govern implementation detail. On conflict between this plan and observed code behavior, verify against code and surface the conflict — do not silently reinterpret the plan.

Stop conditions. Stop and report (rather than improvise) if: (a) the experiment card's kill condition fires — a clean-path verdict cannot be re-derived from snapshots; (b) implementing U1 requires changing the semantics of existing pull/score commands beyond additive storage; (c) any unit requires breaking stored v1 packet rows.

Product Contract

Summary

Detrix scores completed agent traces against deterministic rules and records admission verdicts. Today those verdicts cannot be independently re-verified: a re-pull overwrites the raw trace bytes a verdict was scored against, config content is never persisted (only its hash), evidence pointers are decorative labels with no verifiable digest, and no command replays stored verdicts. Separately, the tool's output language can overstate what post-hoc scoring proves. This plan adds a replay spine and an honesty ceiling.

Problem Frame

Verified from current source:

  • src/detrix/store.py — upsert_trace uses ON CONFLICT(trace_id) DO UPDATE SET raw_json = excluded.raw_json: a re-pull destroys the exact input bytes of earlier verdicts. Verdicts store trace_hash, so drift is detectable but not replayable.
  • config_events rows persist only config_hash (details_json is always '{}'); every command reloads failures.yaml from disk. Verdicts scored under an earlier config are unreplayable after any config edit.
  • src/detrix/engine.py emits a single evidence pointer trace:{trace_id} with no content digest — a label, not checkable evidence. replay_status is permanently "not_run".
  • report/push present rejection counts with no shadow-mode labeling, and the coverage boundary of the deterministic rule set is not stated.

Scope Boundaries

Deferred to follow-up work

  • Claim-admission objects (ClaimContract / ExecutionReceipt / ClaimAdmissionDecision) — a general model is being derived elsewhere; porting a shape now would freeze it prematurely. execution_identity (R7) is the interim slice.
  • Consumer-receipt enforcement beyond the mode label — verifying that a Langfuse consumer actually obeyed a pushed verdict is out of scope; U4 only prevents claiming it.
  • Serving-path semantic canaries — not applicable to a post-hoc scorer; joinability checks already cover the analogous input-integrity concern.

Outside this product's identity

  • Pre-run experiment scaffolding, playbooks, or run fencing — this tool evaluates completed traces only.
  • Training-data export — packets remain post-hoc only (TrainingEligibility stays all-false).

Planning Contract

Key Technical Decisions

KTD1 — Append-only content-addressed snapshots, additive to the existing tables. New tables: trace_snapshots(trace_hash PK, raw_json, first_seen_at) and config_snapshots(config_hash PK, content, stored_at). The existing traces table keeps its latest-view semantics so pull/score behavior is unchanged; upsert_trace additionally inserts-or-ignores a snapshot row keyed by the canonical-JSON SHA-256 already computed as trace_hash. On store initialization, backfill snapshot rows from existing traces rows. No migration shim beyond the backfill — the store schema uses CREATE TABLE IF NOT EXISTS and the project has no released users.
KTD2 — Evidence pointers become verifiable: required 64-hex content_digest plus fail-closed verification. EvidencePointer gains content_digest (pattern-validated). Pointers use JSON-pointer-style paths (/trace, /observations/0/input, …) resolved into the trace dict. A verify_evidence_pointers(packet, trace) helper recomputes each digest and on any unresolvable pointer or mismatch marks the packet unjoinable and records per-pointer failure reasons in joinability. The engine self-verifies pointers at score time (integrity from birth); replay re-verifies from snapshots. The digest function is the canonical-JSON SHA-256 already implemented as _hash_json in src/detrix/engine.py — promote it to a shared helper rather than adding a second canonicalization.
KTD3 — Replay compares full recomputed packets under a determinism contract. score_trace(trace, config) is already pure (no clock, no randomness — verified). Replay recomputes the packet from the snapshotted (trace, config) pair and compares canonical JSON against the stored packet_json. Row outcomes: MATCH; DRIFT (recomputed packet differs, or a digest check fails); UNREPLAYABLE (trace or config snapshot missing). Any non-MATCH → exit code 1.
KTD4 — The wording ceiling is enforced in code, not convention. report prints a fixed shadow-mode header line and labels counts as would-have decisions; the pushes table gains a mode column (default 'shadow') recorded on every receipt. Raising the ceiling (enforced/prevented language) requires evidence the tool cannot hold today, so no flag to change the wording is added.
KTD5 — Coverage is reported as covered-vs-abstained, not accuracy. Covered = ADMIT + REJECT; abstained = SUPPORT_ONLY + QUARANTINE. Report prints both counts and the abstained share so an abstain-everything configuration is visible. README gains a boundary paragraph: deterministic guarantees hold only within the configured rule set; everything outside abstains.

Assumptions

  • No external users hold a populated .detrix/store.db; the backfill-on-open path in KTD1 is sufficient migration.
  • GateConfig can expose the raw canonical config content (or the loader can return it) without changing content_hash semantics — verify in U1; if content_hash is not derived from the stored representation, store exactly the bytes the hash is computed over.
  • Packet schema v2 is additive (new required fields have defaults or are engine-populated); stored v1 packet_json rows are never rewritten.

Implementation Units

U1Append-only evidence snapshots

Goal
Every verdict's exact inputs — trace bytes and config content — are retained content-addressed; nothing overwrites them.
Requirements
R1, R2
Dependencies
none
Files
src/detrix/store.py, src/detrix/failures.py, src/detrix/cli.py, tests/test_store.py
Approach

Add trace_snapshots and config_snapshots tables per KTD1. upsert_trace also writes an insert-or-ignore snapshot keyed by the canonical trace hash. activate_config (or a sibling called from score) persists the config content keyed by content_hash. Backfill snapshots from existing traces rows during _initialize. Add lookups get_trace_snapshot(trace_hash) and get_config_snapshot(config_hash). Verify how content_hash is computed in failures.py and store exactly the representation the hash covers.

Test scenarios
  • Score a trace, re-pull the same trace_id with different content, score again: both verdicts' snapshots resolvable by their respective hashes; neither overwritten.
  • Edit failures.yaml, re-score: both config snapshots retrievable by hash.
  • Open a store created pre-change (fixture built with old schema): backfill populates snapshots for existing traces; subsequent replay of those verdicts works.
  • Snapshot insert is idempotent: scoring twice writes one snapshot row.
Verification

Store tests green; a verdict's (trace, config) pair reconstructs from the store alone with the failures.yaml file deleted from disk.

U2Digest-verified evidence pointers + execution identity

Goal
Evidence pointers become checkable claims; packets self-describe what produced them; schema v2.
Requirements
R3, R7
Dependencies
none
Files
src/detrix/admission.py, src/detrix/engine.py, tests/test_gates.py (or new tests/test_admission.py)
Approach

Per KTD2: promote _hash_json to a shared canonical-digest helper; add required content_digest to EvidencePointer; engine emits real JSON-pointer paths with computed digests (whole-trace pointer at minimum; per-observation pointers where a gate's evidence names a field). Add verify_evidence_pointers(packet, trace) failing closed into unjoinable + failure list in joinability. Populate execution_identity (detrix package version, Python version, config hash). Bump ADMISSION_PACKET_SCHEMA_VERSION to 2; never rewrite stored v1 rows.

Test scenarios
  • Scored packet's pointers all verify against the input trace (round-trip).
  • Tamper one trace field after scoring: verification reports digest_mismatch:<pointer> and the packet goes unjoinable.
  • Pointer to a missing path reports unresolvable_pointer:<pointer>.
  • Malformed digest (non-64-hex) rejected at model validation.
  • v1 packet JSON still parses where read paths touch stored rows (report over a store containing v1 + v2 rows).
Verification

New verification tests green; demo output unchanged in decisions while packets now carry digests and execution identity.

U3detrix replay command

Goal
One command proves every stored verdict re-derives from snapshots — the tool's reliability claim becomes checkable by anyone.
Requirements
R4
Dependencies
U1, U2
Files
src/detrix/cli.py, src/detrix/store.py, tests/test_cli.py
Approach

Per KTD3: iterate stored verdicts (all rows, not latest-only); for each, load both snapshots, reconstruct GateConfig from snapshotted content, recompute score_trace, verify evidence digests, compare canonical JSON to stored packet_json. Print one line per row (trace_id config_hash OUTCOME) plus a summary; exit 1 on any non-MATCH. Add --json for machine-readable output. Update replay_status semantics: report can now distinguish replayed rows.

Test scenarios
  • Clean path: pull → score → replay = all MATCH, exit 0.
  • Tamper a trace_snapshots.raw_json row: replay reports DRIFT for exactly the affected verdicts, exit 1.
  • Delete a config snapshot row: affected rows UNREPLAYABLE, exit 1, remaining rows still evaluated.
  • Config edit between scores: replay evaluates each verdict against its own config snapshot, not the current file.
  • --json output parses and row outcomes match the text output.
Verification

End-to-end: temp workspace, demo-style traces scored, replay exit 0; the two tamper paths exit 1 with correct labels. This is the experiment card's run.

Definition of Done

  • All five units implemented on a feature branch off main; conventional commits, one logical change each.
  • Verification Contract fully green; replay e2e output preserved in the closing commit or PR description.
  • README updated (shadow-mode ceiling, coverage boundary, replay in the command walkthrough).
  • No dead or abandoned-attempt code in the diff.
  • Stored v1 packet rows remain readable; nothing rewrites history.
